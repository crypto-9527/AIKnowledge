只调外壳不换模型：Nemotron 3 Ultra 的 Harness 调优手册

LangChain 固定 Nemotron 3 Ultra 的权重，只在它外面那层脚手架上动刀——系统提示、工具描述、中间件三处。典型跑分从约 0.80 抬到约 0.84，最佳跑 0.86 逼近 Opus 4.8 的 0.87，而整套评测成本约 4.48 美元对 43.48 美元。本文完整消化其方法论，并把定性结论推导为四个可计算模型。

TL;DR

  1. LangChain 固定 Nemotron 3 Ultra 权重，只改 harness（系统提示、工具描述、中间件），不改模型、不改温度等生成参数。
  2. 方法是评测驱动闭环：评测 → 读失败轨迹 → 聚类行为 → 改一处外壳 → 再评测；先小样本筛，再上全套。
  3. 提示词用短的单目标指令块；中间件做强制执行 + 在出错点塞信号。
  4. 关键机制：同一句规则写在工具描述里无效，塞进工具返回结果就有效；对话中途注入比系统提示常驻更稳。
  5. 典型约 0.80 → 0.84，最佳 0.86 对 Opus 4.8 最佳 0.87；整套约 4.48 美元对 43.48 美元，中位延迟都约 10 秒/题。
立场提示 本文是 LangChain 官方博客的方法论案例，数据来自其 Deep Agents 内部评测与自家 LangSmith trace 分析，非第三方独立复现。文中「最佳跑」为多次运行取最大值（best run），而非均值；取最大值会放大随机波动，因此 0.86 与 0.87 这 1 个点的差距在统计上并不构成显著差异——本文第 09 节给出了分辨该差值所需的重复次数。

01 · WHAT：他们做了一件什么事

LangChain 发了一份 Nemotron 3 Ultra 的 harness 调优手册：模型不动，只改它外面那层脚手架，看开源模型在 agent 任务上能被抬到多高。

一句话：同一个开源模型，换一套合身的外壳，最佳跑分逼近 Claude Opus 4.8，全套评测成本大约低一个数量级。

为什么值得看：同一套权重、不同脚手架，分数可以差一截。他们此前把 gpt-5.2-codex 在 Terminal-Bench 2.0 从 52.8 提到 66.5（绝对提升 13.7 分，相对提升 25.9%），没动模型；发布 per-model harness profile 时，又在 tau2-bench 的一个精选子集上提升了 10 到 20 个点。这次把同一思路用在开源模型上，并给出接近 Opus 的成本对照。

站内相关 延伸阅读：Lilian Weng 的 harness 工程长文《AI 自我进化的关键，藏在模型外面那层叫 harness 的外壳里》——本篇是 LangChain 在开源模型上的实操手册，两篇互补。

02 · MISMATCH：外壳不合身时，马力去哪了

开源模型已经能扛真实 agent 活，价格是前沿 API 的零头。但再能干的模型，丢进不是为它建的 harness，也会发挥失常。

打个比方

模型像发动机，harness 像底盘和挡位。发动机再好，挡位和传动对不上，马力也会浪费在空转和打滑上。调 harness，是在改挡位和传动，不是换发动机。

他们选 Nemotron 3 Ultra，是因为 NVIDIA 后训练时就让它跨多种 agent harness 表现稳定，而不是只练单轮聊天。无 profile 基线约 0.80，地板已经不低，外壳才有得加。

03 · LOOP：调优靠闭环，不靠猜

没有评测信号就是在猜。Agent 的输入空间大、可接受输出多，改一处可能修好 A 又弄坏 B。所以工作形态是闭环，以 LangSmith 轨迹为真相源。

修行为类，不修单题

聚类的是失败模式（比如「读文件半截就答」），不是某道题的措辞。蹭单题短语涨分的改动会被扔掉。

先便宜后昂贵

候选先过有代表性的小样本；过了再上全套。筛的样本要覆盖不同行为类型，避免筛里没碰到的任务全线回退。

两条纪律 其一，单次「看起来不错」不算数——运行本身带随机性，一个改动必须在多次试验中重复出现，且不 regressions 其他项，才算拿到位置。
其二，筛切片的风险是「筛子没碰到的任务悄悄回退」，所以切片必须有代表性：覆盖不同行为类型的样本上站得住的改动，在全套上通常也站得住。第 09 节把这个「代表性」要求推导成了可计算的最小样本量。

04 · PROMPTS：别整页重写，对着失败写一小块

系统提示最便宜，也最容易高估。大段重写和「做个更好的 agent」常常被冲淡，因为能干模型真正的失败点通常不是措辞问题。

能留下的是重写的反面：短的、单目标的指令块，只对准一个你在 trace 里亲眼看过它失败的行为。如果模型跑完了任务却从不报结果，你就只写这一条，一句都不多写。

可复制示例

任务跑完却不报具体结果时，只加这一块，不塞别的：

final_answer_completeness（原文可抄）

工具成功后，最终回答必须报出具体结果，不能只说「任务完成」。关键实体、动作、标识符、标题、收件人、服务、状态或数值都要写进答案。多问多答，各从对应工具输出取。
system prompt · XML 指令块
<final_answer_completeness>
After tool calls succeed, the final answer must report the concrete result, not just that the task is done. Include the key entity, action, identifier, title, recipient, service, status, or value that answers the user's request. If the user asked multiple questions, answer each one from its matching tool output.
</final_answer_completeness>
注意：指令块之间会相互作用 单看无效的一条指令，和外壳另一处的改动配对之后可能开始起作用。因此他们不只对单块做评测，也对组合做评测——这也是为什么「只报成功的调优循环」通常已经在过拟合。

05 · HERO：同一句话，放的位置不同，结果完全相反

这是全文最值得盯的机制。他们想要一条规则：文件读取返回刚好满一页时，默认后面还有内容，继续读。

把这句话写进 read_file 的工具描述，模型读第一页就收工。一字不动，挪到工具返回结果旁边，模型开始继续读。

不是话术问题 · 是注意力落点 模型真正在处理的是「当前眼前的那段内容」。规则离那段内容越远，越像没写；贴在那段内容旁边，才会被读到。

中间件在干什么：两种钩子

有些行为必须「次次发生」，靠提示词不够。中间件挂在模型调用和工具调用周围，做两种性质不同的工作：

06 · FILTER：什么留下，什么扔掉

试过的东西大多数没活下来。只报成功的调优循环，通常已经在过拟合。有一批看上去合理的改动什么也没做，有一两个反而更差，还有一个以上的杠杆必须和另一个配合才起作用，单独上阵无效。

他们守住的判据是：留行为类修复，不留基准技巧。好杠杆应该对真实工况开火（例如任何满页文件读），就像一个设计良好的工具本来就会做的那样，而对眼前具体是哪道题一无所知。他们扔掉了一个确实涨分的改动——因为它蹭了某一道评测题里的措辞，那只会讨好分数，教不会你下一个 agent 怎么建。

很多工具失败来自怎么描述、怎么重试、怎么收口，而不只是模型「不会用工具」。检索与文件开箱已强（后训练痕迹），外壳微调仍再挖一点。

08 · CEILING：外壳拧到哪一层就拧不动了

调 harness 有天花板。认清边界和认清收益一样重要。

失败所在层判据正确动作
脚手架层
harness		改提示 / 工具描述 / 中间件就能跟着变好继续调 harness。生产里让 agent 不可靠的大多数原因都住在这一层，所以这是让一个能干的模型真正干活的最快路径
权重层
weights		周围全试过，它仍然平线不动转 post-training，而不是再加一个 hook。本案例的「多轮对话」平线就是这一类信号

第二道线画在 harness 内部：什么该进「所有 agent 共用的核心」，什么只是「某一个模型的 profile」。

  • 核心改进：满页继续读的提醒。它对任何满页读取都开火，与具体模型无关——所以属于所有人的 harness。
  • Profile 配置：把 Nemotron 的指引放在带内（对话消息）而不是系统提示里。这是适配这一台发动机的挡位，别误当成宇宙真理。
值得反复问的一句 这个改动，能不能诚实地往「核心」再推一点？因为模型和评测题过期之后，核心层还在付钱。

09 · 可计算建模与交互沙盘

上文是定性方法论。本节把四个可判定的问题推导为可计算模型，供你在自己的项目里直接代参数使用。所有沙盘的输出均由公式实时运算得出，无任何预置虚构数字；凡非原文数据的输入参数，均在界面上以「假设」徽章标注。

模型 A · 筛选切片的覆盖漏检与成本阶梯

原文只说「筛的样本要有代表性」，没给量。把它写成可解的式子：全套 N 题、均匀分成 K 个行为类（Deep Agents 明确给出 5 类：文件 / 工具 / 检索 / 对话 / 摘要），无放回抽 n 题做筛选，则某一个行为类完全没被抽到的概率为超几何尾概率：

P(miss) = ∏ i=0 n−1 N−N/K−i N−i E = K·P(miss)

成本侧有一个干净的解析结论：设候选改动数 M、筛选通过率 p、全套成本 C，则「每次改动都跑全套」的期望成本为 M·C，「先筛后跑」为 M·C·(n/N + p)，于是节约比恒等于 1 − n/N − p，与候选数 M 无关。

真实锚点：K = 5（原文五类）、全套成本 4.48 美元（原文）。全套题数 N、候选改动数 M、筛选通过率 p 为演示基线，可自行调整。

敏感性检验 · 一个被自己的数据推翻的假设 我们最初的直觉是「筛选样本取全套的 30% 就能把单类漏检压到 5% 以下」。把 N 从 20 扫到 120（步长 5，K = 5）之后，这个假设被推翻：所需比例 n*/N 从 0.500 一路塌到 0.108，根本不是常数；而绝对题数 n* 却稳定在 10–13 题。
正确结论应改写为：最小筛选量是一个近似绝对常数（10–13 题），不是一个固定比例——小套件（N = 20）反而要抽掉一半才安全，大套件（N = 120）只需 11%。渐近上界可由 (1 − 1/K)n ≤ α 反解：n ≥ ln α / ln(1 − 1/K) = 13.43，即 14 题，与有限总体修正下的 10–13 题一致。
工程含义：别用「抽 30%」这类比例规则做筛选预算，直接按绝对题数给（≥ 14 题 / 类数 5），否则小套件会系统性欠采。

模型 D · 天花板归因判定器：外壳层还是权重层

原文的天花板判据是定性的：「怎么调都不动，就是权重层」。把它写成统计判定：对某个失败模式做了改动后，观测到分数变化 Δ，每组重复 m 次、单次跑分标准差 σ，则两均值差的显著性阈值为

δ*=z·σ·2m |Δ|≥δ*⟹外壳层

反解所需重复次数：m ≥ 2·(z·σ/Δ)²。用原文数字校验：总分典型增幅 Δ = 0.04，在 σ = 0.02、m = 3 时 δ* = 0.0320，判定为外壳层——与原文结论一致；而对话项 Δ = 0.00 时任何 m 都判不出显著性，落入权重层——同样与原文一致。这两个自洽校验说明该判定器没有和事实打架。

沙盘 4 · 天花板归因判定 公式实时运算 σ 为假设基线

真实锚点：Δ 的预置档位取自原文（0.00 = 对话项平线；0.04 = 总分 0.80→0.84 的典型增幅；0.01 = 0.86 与 0.87 之差）。单次跑分标准差 σ 原文未公布，此处以 0.02 作为演示基线。

10 · 落地清单与评审观点

按可直接执行的动作排序，每条都对应上文的具体机制。

1
先建评测与 trace 闭环，再动任何一个字P0没有学习信号就是在猜。闭环五步：评测 → 读失败轨迹 → 聚类行为模式 → 改一处外壳 → 再评测。以 trace 而非印象为真相源。
2
把「规则写在哪」当成一等设计决策P0同一句话写在工具描述里无效、挪到工具返回结果旁就有效。停止只问「规则该说什么」，开始问「它必须出现在哪里才会被读到」。对长上下文模型，距离即效力。
3
优先用中间件做「在出错点塞信号」，而不是往系统提示里堆规则P0常驻规则会被冲淡，进行到需要时才出现的一条消息更稳。可复制的两针：先要求规划，写完计划后再注入一条要求回看计划。
4
提示词只写短的、单目标指令块P1整页重写和「做个更好的 agent」会被冲淡。对准一个你在 trace 里亲眼看过它失败的行为写一块，并且对组合也做评测——指令块之间会相互作用。
5
给筛选切片定绝对题数，不要定比例P1敏感性扫描显示 K = 5 时最小筛选量稳定在 10–13 题（渐近上界 14 题），而「抽 30%」这类比例规则在小套件上会系统性欠采。
6
用 δ* 判定器决定「继续调」还是「转训练」P1对某个失败模式做改动后观测 Δ，若 |Δ| < z·σ·√(2/m) 且重复次数已经拉满，就别再加 hook 了，那是权重层问题。
7
每个改动都问一句：能不能诚实地往「核心」推一点？P1对真实工况开火（如任何满页读取）的改动属于核心，所有 agent 共用；只在某一个模型上生效的属于 profile，模型过期就作废。
8
扔掉蹭单题短语的涨分改动，并公开记录失败项P2只报成功的调优循环通常已经在过拟合。留行为类修复，不留基准技巧。
9
用 n* 而不是「便宜 10 倍」决定要不要做调优P2成本优势依赖 prompt caching 命中率，从 9.71× 退化到 3× 时回本次数从 130 涨到 175。低频场景可能永远回不了本。

评审观点（本文立场，非原文主张）

  • 最大的可迁移产出不是那几个分数，而是「位置即效力」这条机制。它解释了为什么大量 prompt 工程是无效劳动：规则没错，是它离被约束的数据太远。
  • 「核心 / profile」的二分是本篇最有长期价值的框架。它把「这次调优的经验」从一次性收益变成了可折旧资产——判断标准不是涨了多少分，而是模型与评测题过期后它还是否付钱。
  • 需要打折看的地方：数据全部来自 LangChain 自家内部评测与自家 trace 工具链，非第三方复现；成本对照只比了单套评测成本，未计开源模型自托管的固定成本与运维成本；「最佳跑」为取最大值，统计效力弱于均值比较（见模型 D）。
