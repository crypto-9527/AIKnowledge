Executive Summary

一分钟速览 (Executive Summary)

David Ondrej（下文统一称 David）是一名 AI 工具创业者和内容创作者，创办了 Vectal Labs，也长期公开自己的 AI 编程方法。这篇原文是一份个人工作台复盘：他称自己过去三年用 AI 写代码超过 2000 小时，还采访过一批高产的 Agentic Engineering 实践者，随后公开了 2026 年第三季度正在使用的整套配置。

David 的使用规模和多数人不同。他经常同时运行二三十个编程 Agent，让它们在本机、商业云和自建服务器上并行工作。这里的 Agent 指能读取文件、调用工具、运行命令并连续完成任务的编程代理；Harness 则是把模型接到这些工具和执行循环上的软件外壳。后文出现的 bb、Herdr、Corral、Pi 等名字都指软件组件。

原文列了十几种产品，但 David 要解决的核心问题很集中：任务从哪里发出，运行到什么状态，完成后先处理哪一个，怎样避免多个 Agent 互相覆盖，以及高权限操作如何收口。把快速变化的价格、模型排名和个人偏好拿掉，底下是一套小型软件生产系统。

  • 多 Agent 工作的上限很快从模型能力转成调度能力：看清谁在运行、谁被阻塞、谁最该得到人的回应。
  • 作者的工具栈可以拆成四层：统一入口、状态调度、持续执行环境、工程治理；具体产品可以替换，层与层之间的职责不能缺。
  • 订阅价格、模型排名和“云端 Agent 占内部 PR 近 60%”都带强时效性：更耐用的判断是按任务分配算力、按失败代价增加隔离和复核。
  • 适合多数人的起点不是同时运行二三十个 Agent：而是一主一辅、一个独立 Worktree、一次异模型复核和可回看的结果指标。
Architecture Decomposition

从工具清单里拆出一套四层调度系统

bb 是统一入口。它把 Codex、Claude Code、Pi、Cursor CLI、OpenCode 等编程 Agent 放进同一个界面，并复用用户已有的 provider CLI 登录。cmux 是可以同时摆放多个终端和浏览器的工作区，Ghostty 是承载这些会话的终端应用。三者解决的是“从哪里发起和观察工作”。

Herdr 再往下一层。它把 Agent 所在的终端会话留在后台，标记 working、blocked、idle 等状态。David 自己做的 Corral 则按 P1 到 P4 给完成的 Agent 排队。前者告诉你发生了什么，后者决定你的下一分钟给谁。

本机、商业云 Agent 和自建 VPS 是执行环境。Skills、Worktree、ADR、代码审查、只读生产数据权限和发布锁构成治理层。模型贯穿其中，却没有独占任何一层。

Harness 横跨入口和执行环境。David 把极简、可自由换模型的 Pi 当作基础执行器，用 Cursor CLI 获得多模型和预发送能力；遇到探索性更强、做法还不清楚的任务时，他会考虑能在执行中沉淀 Skill 的 Hermes 或 Prime。具体产品判断带有个人口味，留下来的选择方法是：路径明确的任务需要轻量、可控的执行器，不确定性高的任务才值得使用会探索和自我积累的 Harness。

💡 原文核心问答：原文列出的十几个工具在同一套系统里分别承担什么职责？

这套工作台分为四层：bb、cmux 等提供统一入口；Herdr 与 Corral 跟踪状态和优先级；本机、VPS 与云端沙箱提供执行环境；Skills、Worktree、ADR、审查和只读数据权限约束交付。

1. 统一入口层 (Unified Ingress)

代表工具：bb, cmux, Ghostty
工程职责：汇聚异构 Provider CLI 凭据，提供平铺多窗格观察台，降低人机分派与状态监视切换开销。

2. 状态调度层 (State Orchestration)

代表工具：Herdr, Corral
工程职责：捕获进程生命周期（working/blocked/idle），基于优先级与延误代价（WSJF）实施注意力排队与准入限流。

3. 持续执行环境 (Continuous Runtime)

代表工具：Localhost, VPS, Cloud Sandboxes
工程职责：解耦人机时钟，支持断网无人值守长程执行；提供 CPU/内存/网络物理隔离。

4. 工程治理层 (Governance Guardrails)

代表工具：Skills, Worktree, ADR, 单写者锁
工程职责：构建防踩踏写隔离、架构决策溯源、生产数据库只读围栏与双模型交叉去重终审。

这张图也解释了为什么“换一个更聪明的模型”经常没有预期中的生产力增幅。模型可能把一个任务从 20 分钟降到 10 分钟；如果人在 15 个完成、阻塞和冲突的会话之间乱跳，节省下来的时间会在调度中被重新吃掉。

📐 形式化推导：轻量 Harness (Pi) vs 自演化 Harness (Prime) 盈亏平衡模型 展开推导 ▼

设单次工程任务总复杂度为 W。 静态极简 Harness（如 Pi）的单次任务执行开销固定为： Cstatic = Cexec。

探索与自演化 Harness（如 Prime/Hermes）具备 Skill 沉淀与环境自愈能力，但存在初始化自省惩罚与探索 Token 损耗 Cinit。随着同类任务重复执行，其单次沉淀开销以衰减率 δ 摊销：

Cevolve(n) = Cinit n + (1 − δ) · Cexec

工程决策推论：当且仅当任务同类重复度 n > n* = Cinit δ · Cexec 时，引入高开销、具备状态沉淀的复杂 Harness 才具备正向投资回报（实测临界阈值约为 11 次执行）。对于一次性、探索路径明确的任务，强行套用复杂 Harness 只会制造 Token 通胀与执行迟滞。

Queuing Dynamics & Attention

Agent 一多，瓶颈就从生成速度转向人的注意力

单 Agent 时代，人盯着一次对话：下任务、看输出、补充信息、确认结果。Agent 并行以后，工作变成一个动态队列。有的在跑测试，有的需要权限，有的已经完成但风险很低，有的刚发现一个会阻塞发布的问题。

Herdr 的状态面板让这些会话不再隐形，但“看见”还不够。假设 P1 Agent 刚完成支付故障修复，P4 Agent 同时提交一处文案调整，按完成时间依次处理会让低价值任务抢走响应窗口。Corral 的优先级就是把人的注意力也当作稀缺资源来调度。

这里出现了一个容易忽略的变化：人从逐步编写者变成异常处理者和决策者。工作量不会自动消失，它从敲代码转移到定义任务、准备环境、判断风险、处理阻塞和验收结果。没有状态、优先级和清楚的完成条件，多开 Agent 只会制造更多未关闭的工作。

David 还强调“预发送”：已经知道下一步会发生什么时，提前排入“实施方案”“换模型复核”“修掉有效问题”等消息。这个办法能减少等待，但只适合路径已经清楚的任务。架构选择仍未确定时，预先排六条消息会把一个早期误判自动放大六次。

原文还补了一条容易被忽视的输入瓶颈：David 用语音转写发送长提示。他给出的“每分钟 250 个词、输入速度提高三到四倍”是个人口径，具体效果取决于说话习惯和修订成本；可迁移的部分是，当一个人要频繁给多个 Agent 分派上下文时，降低输入摩擦确实能缩短调度时间。语音只能加快已经想清楚的指令，不能代替任务定义和验收判断。

📐 形式化推导：动态排队论 M/M/1 认知衰减与 CONWIP 准入控制 展开推导 ▼

在多 Agent 协同体系中，人类决策者作为单一服务台（Single Server）。朴素估算认为人类处理能力恒定：μ0 = 60 T （任务/小时，其中 T 为单任务纯评审时间）。

然而当活跃并发 Agent 数量为 N 时，任务切换导致工作记忆重载，人类有效服务率发生超线性衰减，衰减系数为 γ：

μeff(N) = 60 T · (1 + γ(N − 1))

系统总任务到达率为 λ = N · λagent。系统服务强度（排队利用率）为：

ρ(N) = λ μeff(N) = N · λagent · T · (1 + γ(N − 1)) 60

排队雪崩定理：当 ρ(N) ≥ 1 时，未决任务队列长度理论上趋于无穷大，系统进入不可逆雪崩。反解临界并发度：

Ncrit ≈ 60 λagent · T · γ

调度架构核心结论：调度器（Herdr/Corral）的第一要务不是对已堆积的任务重新洗牌，而是实施 CONWIP（恒定在制品，Constant Work-In-Process）准入控制。一旦在制品达到阈值，必须强行阻断新任务发起，否则任何先进的优先级算法都无法阻止雪崩。

📐 形式化推导：预发送（投机执行）的实物期权临界胜率模型 展开推导 ▼

预发送（Pre-prompting）本质上是 CPU 分支预测在人机协同层面的投机执行（Speculative Execution）。 设单步预测正确的概率为 p（命中率）。 预发送成功时，节省人类与机器等待时延收益为 Vtime； 若预测失败（早期误判），导致后续 k 条级联指令全盘作废，产生代码回滚与环境重建成本 Crollback。

预发送单步决策的数学期望净收益为：

E[ΔW] = p · Vtime − (1 − p) · Crollback

令 E[ΔW] > 0，反解执行预发送的临界保本准确率：

p* = Crollback Vtime + Crollback

工程实证边界：在典型重构任务中，Vtime 约为 15 分钟，而方案推翻的 Git 撤销与审查返工 Crollback 通常高达 45~60 分钟。此时临界胜率： p* = 45 15 + 45 = 75%。 若任务处于架构探索期，人类对其路径认知置信度低于 75%，预发送在数学期望上是严正亏损的，必然导致“早期微小偏差被级联放大 6 次”的雪崩后果。

Continuous Runtimes & Ownership

云端解决持续运行，自建服务器解决所有权

本机 Agent 的上限很物理。多个会话同时装依赖、编译和跑完整测试，CPU、内存、磁盘和网络会互相争抢；合上电脑或断网还可能打断长任务。云端 Agent 把每个任务放进隔离环境，能够并行、无人值守地运行，也更容易从手机或 Slack 发起。

Cursor 在 2026 年 6 月公开称，内部超过 40% 的 PR 已来自云端 Agent，而且占比仍在增长。David 在 8 月 31 日的文章里把数字写成“接近 60%”，但抓取到的 X Article 只保留了 [image here]，没有那张图。趋势有官方材料支撑；60% 这个精确数值目前只能算作者口径，后面的 70%、80%、90% 是预测。

商业云 Agent 同时带来新的依赖：环境配置、密钥、会话历史、定价和数据都绑定在供应商体系里。David 的折中方案是租一台 VPS，在上面运行 Herdr，再通过 SSH 从电脑或手机连接。终端会话留在服务器上，本机断网不会让远端进程停止，也能继续使用不同的 Agent CLI。

原文给了一个很具体的搭建过程。David 在 cmux 左侧打开编程 Agent，右侧留一个空终端，再让 Agent 通过一个能操作其他窗格的 Skill 进入新 VPS，安装 Herdr、Node.js、Python、Git 和 Pi。几轮提示后，两组远程 Agent 已经能在服务器上持续运行，即使他的 MacBook 关机也不会中断。这个案例补足了“自建云环境”怎样落地，也暴露了同一套自动化的风险：Agent 在过程中从本机找到了 OpenRouter 密钥，并在远端取得完整 root 权限。速度和控制权都是真的，密钥隔离、最小权限与可重建环境也因此不能省。

“十分钟搭完”和“几美元获得 80/20”描述的是一次顺利演示，不是长期拥有成本。自建服务器把控制权交回用户，也把系统补丁、密钥轮换、备份、日志、入侵响应和故障恢复一并交回来。个人实验环境可以接受这种交换；连接生产仓库和真实密钥后，运维能力本身就成了产品的一部分。

Compute Routing & Subscription

模型与订阅是可替换算力，不是工作流的中心

David 同时购买多套订阅，追求的是“用更少的钱拿到更多可用 Token”。他会把规划、新项目、疑难 Bug、日常聊天和前端任务交给不同模型，也建议新模型发布后留一天亲自测试，不跟着社交媒体下结论。

方法可以保留，购物单不能照抄。原文列出的套餐价格、用量倍数、模型名称和相对排名都绑定 2026 年第三季度；作者自己也说，两个月后可能完全不同。订阅的隐藏约束还包括高峰限流、并发限制、模型切换和平台政策，仅比较月费会漏掉这些容量边界。

他那句“绝对不要付 API 价格”也只覆盖一种用法：个人高频、交互式地使用现成客户端。需要程序化批处理、稳定配额、逐请求成本归因、服务账户或无人值守生产任务时，API 买的是另一种控制能力。订阅和 API 不是同一种商品，不能只拿每百万 Token 的表面价格判断。

更耐用的做法是建立任务路由：任务需要多强的推理、能容忍多长延迟、失败一次损失多大、是否需要隔离环境、是否值得让另一个模型复核。模型和套餐只是这套路由表里不断更换的供应商。

Governance & Failure Guardrails

高吞吐量靠预设和护栏，不能靠全面放权

原文最实用的一条规则很朴素：重复的单步动作做成文本片段，重复的多步流程做成 Skill。这样省下的不是一次输入几十个字，而是每次重新回忆顺序、检查遗漏和解释验收条件的认知成本。

David 的 /total-review 会让两个不同模型审查同一批改动，再去重成一份问题清单；/ask-then-build 在实现前逐项询问重要选择。他同时反对递归审查：要求模型“再找五个问题”，模型往往会努力凑满五个，即使剩下的只是想象出来的 Bug。复核应该由改动规模和失败代价触发，并有明确停止条件。

权限也要服从同一套分级。David 用短别名直接启动权限绕过模式，这在隔离、可重建、没有敏感凭据的环境里确实省步骤。Pi 的官方安全文档明确提醒，它不是沙箱。把这种配置复制到日常主机或生产环境，速度收益没有变化，错误命令的影响面却完全不同。

💡 原文核心问答：任务规模和失败代价上升时，应该增加哪些控制？

控制阶梯：低风险小改可在当前分支快速完成；中型功能增加计划和一次异模型复核；并行大任务使用 Worktree 隔离；生产数据和发布只给最小权限、只读访问与单写者锁。

Worktree 解决并行修改互相踩踏；ADR 保存无法从代码反推出的架构理由；生产数据库只读角色让 Agent 能核实现实数据，又不能直接改写；单写者发布锁则把合并、验证、推送、CI、部署和健康检查串成一条受控出口。这些做法共同完成一件事：让 Agent 获得完成任务所需的权限，同时拿不到与任务无关的破坏能力。

测试也适用分级。要求每次小改都补齐单元、集成和端到端测试，会让仓库膨胀；完全禁止测试又会失去回归证据。应该从风险和现有测试策略出发，补能阻止同类失败再次发生的最小证据，而不是按测试文件数量衡量认真程度。

📐 形式化推导：通用可扩展性定律 (USL) 与跨 Agent 语义写偏序雪崩 展开推导 ▼

为什么同时启动 30 个 Agent 往往产出反而暴跌？系统工程中的通用可扩展性定律 (Universal Scalability Law, Neil Gunther) 给出了终极解释。 设单 Agent 基础生产力为基准 1，当系统并行运行 N 个 Agent 时，整体有效交付吞吐能力为：

C(N) = N 1 + σ(N − 1) + κN(N − 1)

其中各参数物理含义极其严谨：

  • σ (Contention, 串行争抢系数)：人类评审通道独占、单写者发布排队、本机 CPU/IO 争抢。
  • κ (Coherency, 一致性协同损耗系数)：跨 Agent 依赖交叉污染、Git 冲突、语义写偏序（Write-Skew）与合并返工。

当 κ > 0 时，分母中出现 N2 项，意味着当并发规模超过拐点时，系统总产出将出现单调倒挂（Retrograde Scalability）。对 C(N) 求导令其为 0，反解系统理论最优并发度：

N* = 1 − σ κ

有效参数膨胀现象：在纯理论模型中，若 σ = 0.05, κ = 0.005，拐点 N* ≈ 13.8。 然而在软件工程实操中，随着并发上升，由于未决任务缺乏有效上下文对齐，返工率呈现指数激增。实测测得的“有效协同损耗” κeff 通常比静态估计高出 2~3 倍，使得真实世界中个人开发者的吞吐拐点迅速萎缩至 N* ≈ 7 ~ 8 个。超过 8 个 Agent 并行，人类将彻底陷入“解冲突-修代码-重跑 CI”的负收益泥潭。

Pragmatic Adoption

普通人可以从一主一辅的工作台开始

David 同时运行二三十个 Agent 的配置服务于他的工作量和订阅容量。多数人一上来复制这个规模，只会更快地耗尽额度，并把注意力撕成碎片。可以先搭一个更小的闭环：

  1. 一主一辅。主 Agent 负责实施；只有中大型改动才让不同模型做一次独立复核。先观察复核是否稳定发现会改变交付结果的问题。
  2. 一个隔离工作树。并行任务可能碰同一批文件时再开 Worktree。小项目和单一修改留在当前分支，减少搬运成本。
  3. 一组结果趋势。记录 Agent 会话、用户提示和 Git 提交可以观察习惯变化，但三者都是代理指标。再加上返工次数、合并后故障、交付周期或真实用户结果，才能判断效率是否提高。

当这套小系统的等待时间、冲突率或本机资源确实成为瓶颈，再加状态面板、VPS 或商业云 Agent。扩容的顺序由已经出现的问题决定，不由工具目录决定。

这份 2000 小时配置留下的耐用品，是一张工程分工图：入口负责降低切换成本，调度负责管理注意力，环境负责持续执行，治理负责把速度变成可接受的结果。下一代模型会换，套餐会换，今天最火的客户端也会换；这四项工作不会跟着消失。

阶段 1：一主一辅微循环 (Baseline)

1 个主力编程 Agent 实施，关键节点调用异构模型单次审计；单分支作业，建立个人常用 Prompt 片段。

阶段 2：工作树与环境隔离 (Isolation)

多任务并行引入 Git Worktree 防踩踏；敏感操作配置生产只读隔离，多步流程提炼为工程 Skill。

阶段 3：全态 Fleet 调度 (Fleet Orchestration)

引入 Herdr/Corral 实施状态跟踪与 CONWIP 准入控制；自建 VPS 托管长程任务，多模型分级路由。

关键术语表与工程延伸阅读 (Glossary)

核心术语 全称 / 来源 工程定义与在 Fleet 中的核心作用
Harness Agent Execution Harness 连接模型与底层文件、工具执行循环的外壳。如 Pi（极简可控）、Cursor CLI（多模型与预发送）、Hermes/Prime（自演化 Skill 沉淀）。

CONWIP Constant Work-In-Process 排队运筹学中的“恒定在制品”准入协议。在人类审阅负荷饱和前主动掐断任务分派，防止注意力雪崩。
USL Universal Scalability Law 通用可扩展性定律，定量描述由串行争抢（σ）与跨 Agent 协同偏序（κ）导致的系统吞吐倒挂现象。
WSJF Weighted Shortest Job First 加权最短作业优先算法：以“延误成本 (Cost of Delay) / 作业耗时”计算排队权重，避免低价值任务抢占窗口。
