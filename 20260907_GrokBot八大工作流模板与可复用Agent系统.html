SpaceXAI 官方分享的 Grok Bot 的 8 个模板：把工作方法变成可复制的助手

8 个日常助手，展示技能、记忆和工具连接怎样组成可复用的工作方法，以及接收者还需要配置什么。
一分钟速览
  • 资产解耦与复用：模板把常用指令、技能、可分享记忆与插件配置带到新助手，大幅减少反复交代同一工作方法的过程。
  • 外循环衔接内循环：开发案例将背景调研、方案规约、编码执行与截图/视频检查串联，让书签中收藏的新工具变成可以亲手体验的原型作品。
  • 迁移边界意识：复杂模板仍需补齐自己的配置；自定义代码、本地脚本与自建 MCP 服务不会自动随模板迁移。
  • 最小可行起点：先从输入明确、反复发生、结果容易检查的小任务开始，把“下次不想重新交代的要求”固化为模板。

你每天让 AI 做的事，往往有一部分一直重复：先去哪里找资料，沿用什么写法，调用哪些工具，最后拿什么结果回来。每次重新交代这些要求，工作就始终依赖你在旁边补充背景。

Grok Bot 的模板功能，把这些做事方法连同可分享的记忆和官方插件配置打包，让另一个人据此建立自己的助手。Matt Palmer 从事开发者关系与产品工作，目前在 SpaceXAI 任职，过去也在 Replit 和 Conductor 工作过。他在《Using Grok Bot: 8 templates to get inspired》中分享了自己日常使用的 8 个例子：从试用开发工具、修改文稿，到整理联系人、查询停车限制和打电话。

这些例子值得一起看，因为它们把“复用一个助手”需要保留什么讲得很具体：既有任务怎么做，也有它去哪里取信息、怎样把结果交到人手上。

模板复制的是一套做事方法

先用写作助手理解模板。你希望它按熟悉的写作原则修改句子，记得你的偏好，还能从 Notion 取稿、把草稿放进 Typefully。只分享一句“帮我润色”，接收者就得自己补上这些要求和连接。

模板把相关指令、技能、记忆与官方插件组合起来。技能（Skills）规定具体动作，记忆（Memory）保留可复用的背景或习惯，插件（Plugins）让助手可以接触对话之外的工具。接收者在自己的环境中使用这些配置，处理自己的资料。

Architecture Blueprint
Palmer 强调：模板是一份重建助手的蓝图。系统会默认排除个人或内部私密数据；接收者得到的版本仍需接上自己的账户、工具与 MCP 连接。

Palmer 在配套教程中强调，模板是一份重建助手的蓝图。系统会选择与工作流有关的内容，默认排除个人或内部信息；接收者得到的版本仍可能与原助手不同，也可能需要额外设置。自定义代码、脚本和自建 MCP 服务不会自动打包，所需插件也要在接收者的环境中安装。MCP 可以简单理解为让 AI 调用外部工具的一种连接方式。

这个区别决定了后面 8 个例子该怎么看：你可以复用作者组织工作的办法，但自己的账户、工具和配置仍需接上。

开发：把任务准备和代码执行接起来

Palmer 的两个开发助手互相衔接。Loops 负责工程任务的准备与组织，Tech demos 负责把新技术变成能检查的演示。

Loops：先把任务交代清楚

Loops 是 Palmer 的软件工程助手。他先与 Loops 讨论，再由 Loops 与 Cursor Agent 沟通；后者是实际执行编码任务的助手。Palmer 把 Loops 称为工程的“外循环”助手。

这里的内外循环有具体分工：代码内循环围绕编写、构建和测试展开；外循环还包括研究、规划、形成方案、部署与检查。写代码只是完整工程过程的一部分。

图 2：软件工程外循环（Loops）与内循环（Cursor Agent）协作架构
Dual-Loop SDLC
代码内循环围绕编写、构建和测试展开；外循环还包括研究、规划、方案、测试和部署。原图把两者分开，提醒我们写代码只是完整工程过程的一部分。

例如修改网站时，Palmer 会让 Loops 阅读几位同事过去的贡献，了解现有做法；也会让它研究竞争产品的文档，思考类似问题如何处理，以及这次修改该怎样验证。Loops 把这些背景整理成任务提示，再启动云端编码助手。之后，Palmer 转到 Cursor 继续工作。

他还把自己反复采用的提示方式保存在助手中。相似任务可以沿用整理背景、形成任务和继续迭代的做法，下一次不用从空白对话重新准备。

定位与动作：先整理背景与方案，梳理同事历史贡献与竞品文档，生成高信息密度提示词，再交给编码助手。
所需工具或数据：
GitHub Cursor Agent

Tech demos：把收藏变成可体验的作品

Tech demos 每天早晨查看 Palmer 的 X 书签，挑一个新工具，发来一份任务提示草稿。这份提示沿用他从 Loops 整理出来的方法，再把开发工作交给编码助手。

Palmer 对返回结果有明确要求：提供截图和视频。演示可以部署到 Cloudflare，用户既能在 Grok Bot 中快速查看，也能打开浏览器实际操作，或者进入 Cursor 继续修改代码。

信息整理：让已有资料直接服务下一次决定

开发助手把资料转成作品。另两种助手则把分散的信息整理成能直接使用的参照，减少“我明明有这些信息，却临时找不到”的情况。

Personal CRM：到一个城市前，先找出当地朋友

Personal CRM 是个人联系人管理助手。它整理 Palmer 在 X 上互相关注的人，并写进 Notion，按国家、州和城市组织。旅行前，他就能筛出目的地的朋友，再决定联系谁喝咖啡或散步。

配套演示把过程讲得更清楚：助手从公开个人简介读取地点，通过接口或浏览页面取得信息，再建立 Notion 数据库。表中保留简介、地点和位置判断的置信度等字段。位置本来就可能含糊，整理后的记录也需要保留这种不确定性。

X algorithm 助手结合 X 算法仓库与原生 X 连接，帮助 Palmer 判断什么时候发帖、采用什么格式，以及如何参与互动。它接手的是内容安排时反复出现的小决定。

Palmer 同时保留了优先级：好内容比细小优化更重要。他觉得这个助手最有用的时刻，是自己拿不准怎样安排内容时。它可以减少犹豫，无法把内容质量这个问题省掉。

内容制作：把质量要求放进重复工序

当工作开始产生文稿、图标等内容，模板还可以保存你希望结果遵循的标准。

Writing Bot：保留人的写作，再接手整理和修句

Palmer 的 Writing Bot 以他喜欢的写作书为基础，包括《Style: Lessons in Clarity and Grace》和《On Writing Well》。他通常先自己写，再让助手处理语法和难写的句子；Typefully 与 Notion 连接让助手能直接处理已有草稿。

这篇 8 模板介绍的准备工作也用了它：Writing Bot 先向他的其他助手索取摘要，再把草稿放进 Typefully，供他开始写作。它既能处理句子，也能把散落在不同助手里的信息收拢到一个写作起点。

Image Generation：让一组资产保持同一种风格

图像助手解决的是成套图标和角色的视觉一致性。它先用技能向 Grok Imagine 发送标准化提示，再调用 fal 的去背景模型；Palmer 随后应用统一色板。

这三个步骤各有作用：提示规范约束生成方向，去背景便于后续使用，统一色板让多张资产在同一个项目中看起来协调。把整条流程保存在助手里，就可以在制作下一组素材时继续沿用。

Dial Bot：给助手一条电话通道

Dial Bot 接入 Bland 的通话能力。Palmer 用自己的声音创建了语音配置，并设置 MCP 连接和通话技能，使助手可以代为打电话。他描述的用途包括应对电话语音菜单和等待接通。

短视频展示了一个很具体的任务：打电话询问当天营业时间，听到对方回答后复述确认并结束通话。它展示了电话问答的过程；语音菜单和长时间等待则属于 Palmer 描述的进一步用途。

怎样把自己的工作方法做成模板

看完这些例子，最实际的起点是找一件已经重复做过的事：你知道需要哪些资料，处理顺序是什么，也知道看到怎样的结果才算完成。先把这件事教给助手，再把成熟的方法分享出去。

Palmer 演示的创建和使用过程，可以分成以下几步：

阶段 要做的事 此时得到什么
创建 打开助手右侧设置，选择 Share as template 尚未发布的模板草稿
检查 查看 Context、Integrations 等详情 确认保留了哪些背景和工具
发布 选择团队或公开范围，再点击 Publish 可分享的模板链接
使用 接收者打开链接，在 Grok Bot 中查看详情后添加 在自己环境中建立的新助手
配置 安装所需插件，补充个人设置及未打包的连接 能处理自己任务的工作环境
创建入口、模板详情和分享链接各在哪里？
在设置中创建模板，使用模板卡片查看详情，发布后复制链接。

复杂模板最好附带清楚的安装和配置说明。Palmer 会要求助手想清楚：别人要复现这套工作方式，需要哪些设置、API 密钥或额外工具，再把必要说明写进模板。接收者也应先读 Context 和 Integrations，确认这些内容符合自己的任务预期。

从创建模板到安装使用有哪些区别？
完整教程：创建草稿、检查详情、选择分享范围、添加到自己的助手并完成配置。

这 8 个例子的共同点，是把工作中的重复要求留下来：开发保存任务准备和验收方式，写作保存编辑标准，图像保存制作工序，联系人和停车助手保存查询与整理方法。选择自己的第一个模板时，可以从一句具体的话开始：

选择第一个模板的黄金法则
“下次再做这件事，哪些要求我不想重新交代？”

去模板市场，找一个适合自己的起点

Grok Bot 已开放官方模板市场 Bot Marketplace，把团队和其他创作者分享的机器人集中到一个入口。你可以按工程、销售、营销、设计、个人事务等类别浏览，也可以搜索机器人或创作者的名字。

市场里的任务比这 8 个例子更广：从准备销售线索、协调面试，到整理素材和照料植物，都能找到相应的助手。先挑一个与你手头任务接近的模板，查看它的用途、技能和工具连接，再决定哪些方法值得留下、哪些配置需要换成自己的。
