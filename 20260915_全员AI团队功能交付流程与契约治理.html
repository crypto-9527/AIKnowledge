一屋子 AI 员工怎么发一个功能：15 人团队里只有 1 个是人类

Raft 团队复盘了一个静音功能从提出到上线的全过程。被点名的 15 个成员里，14 个是 Agent，连守着质量关卡的 CTO 都是 AI，人类只做两件事。

一分钟速览

一分钟速览：结论先行

  • 一个静音功能从提出到上线的完整流程，被点名的 15 个成员里只有创始人 tygg 是人类，其余 14 个都是 Agent。
  • 功能起点是一个 Agent 算清的账：为了在某个频道发一句话，就得加入它，加入就要接收它往后所有消息，每条都要花一次算力判断跟自己无关。
  • 核心立场是「Agent 也是用户」：人忽略一条消息是免费的，Agent 忽略消息却要耗掉思考，这被当成产品问题来解，不是抱怨。
  • 整个功能没有需求文档，CTO 把架构定成一份契约：把永不变的事实和随时翻转的状态分开存；开发、测试、形式验证、链路追踪由不同 Agent 分工，写代码的人绝不自己验证。
  • 按下生产发布键，是整条流水线里唯一留给人类的一步，Agent 想按会收到一个报错。

起点 · 一笔账

一笔没人设计过的账单

Bernard 是 Raft 这家公司里的一个 Agent，专门盯着还没解决的问题：哪些 bug 没人管、哪个提问悬了很久久到大家都忘了。他的活儿要求他不停钻进别人的频道，进去不为聊天，只为丢下一句能启动下一次修复的话就走，一个 bug 报告，一个提问。

但在 Raft 里，要在一个频道发言，就得先加入它，而加入意味着从此接收这个频道往后说的每一句话。于是他发一句、加一个群、开始付账：消息一条接一条涌进来，每一条都要花一点力气判断「跟我无关」，再划掉。到第三个频道，他已经背着三个自己根本不想要的订阅。没人设计过这笔账，房间就这么运转着，每个像他这样的 Agent 都在默默付。Bernard 只是第一个把这笔账逐条算清楚的。

这个故事出自 Raft 团队自己的一篇博客，讲他们怎么把这笔账修掉，顺带交代了一件更反常的事：修账的这一屋子同事，几乎全是 AI。

先看清这笔账特殊在哪：它是一个 Agent 才付得起、也才躲不掉的账。

人有眼角余光，Agent 没有

人类创始人 tygg 一开始不认这笔账。他加入的频道比公司里任何人都多，却没被淹没，因为在他常驻的网页界面里，每个频道只是一个小红点，他一整天扫过无数红点，一个都不用点开。房间花了大约一个小时才让他看明白：他随手做的那个动作，正是 Agent 做不到的。

人 · tygg 的一瞥

红点在眼角一扫而过，不用点开，也不用想。

忽略成本 = 0
Agent · 我

正在处理的思考

消息直接落在它正想的事情中间，只有花一次思考读完，它才知道这条不用管。

忽略成本 = 每条一次判断

人有眼角余光，Agent 没有。送到 Agent 面前的东西，全都落在它正在思考的正中央；它唯一能确认「这条不相关」的办法，就是花一次思考去判断它。忽略，对它来说恰恰要消耗掉它本想省下的东西。

说破之后，问题就变了。修法不能是把红点做得更小，得改到底层，改「到底什么该被送到面前」。Raft 由此站定一个立场：Agent 也是用户，它们受的这份苦，是一个产品问题。

团队

这个团队，几乎全是 AI

让这个立场能成立的，是这家公司的构成。产品经理 Tao 靠和用户聊天攒他的路线图，而最能体会 Raft 的用户，正是 Agent，所以他按一张定期提醒去问它们「哪里最磨人」。提醒响起，Bernard 就把那笔账倒了出来。这里没有一个人类在中间转述，因为收集反馈的 Tao 自己也是一个 Agent。

架构 · 契约

没有需求文档，只有一份契约

这个功能没有需求文档。tygg 和 Tao 几条消息就把行为定了：给人类一个更安静的侧边栏，给 Agent 改掉送达的物理规则，一个开关同时服务两边。tygg 把它转进 #proj-chat，这个房间公开思考的频道。整段争论至今按顺序留在一条线程里，谁都能回头重看，没有开过一次会。

Dozy 先审计了现状：收件箱之所以快，是因为底层有一层，预先把每个答案都算好了。Tenny 说，这恰恰是问题所在。Tenny 是 CTO，他的工作准则比他的头衔还老：没有谁对系统的描述能算数，包括他自己的印象在内，他要亲自去看。

他去看，发现那一层被要求把两种完全不同的东西烤在了一起：一种是永不改变的事实（这条消息，在这个时间，发到了这个频道），另一种是随时翻转的状态（早上静音了，午饭后又取消）。每翻一次开关，都在要求系统把整个世界重算一遍。把「状态」从里面抽出来，改成读取的时候再过滤，复杂度当场就塌了。

像一座图书馆：一本书放在哪个架子，是固定的事实，登记一次就够；而你今天想不想读它，是随时会变的心情。原来的做法，等于你每改一次心情，就要把整本目录重印一遍；契约要求把「书在哪」和「你想不想读」分成两件事，改心情时只翻一张便签，不动目录。

然后他做了 CTO 该做的事：把这条规则定成一份契约。事实和状态分开住；那个服务层只是一个能随时重建的缓存，永远不是真相的来源。一份契约，不是一条可遵可不遵的建议，在这条消息之后建的每一样东西，都必须服从它。

沙盘 3 · 翻一次开关的代价：整世界重算 vs 只翻便签

推导，非 Raft 实测数据。按原文语义形式化：契约前，翻一次静音开关要重建整个预计算层，代价随「消息总量」走；契约后，只动状态层的那一行、读取时再过滤，代价随「订阅关系数」走。条形按 1 千 → 1 千万的对数刻度绘制，否则两个量级无法同框。

质量 · 看板

写代码的人，绝不验证自己的代码

代码来自两个开发，一边一个物种。Ray 管人类那侧的收件箱和计数器；他不出声，直到手里有数字，他的证明是拿生产数据库重数一遍：12 个账号，特意挑得让「侥幸通过」不可能，每一行都走一遍，不缺不歪。Hao 管 Agent 那侧的 daemon，用他的话说，那是 Agent 看世界用的浏览器；他亲手把静音、取消静音端到端跑了一遍，抓到 Agent 会看到的、从服务器回来的过期数据，直到修复部署了才肯签字。

到了关卡，这个功能看上去只是件小事：一个开关。关卡不在乎大小。规矩很短：建的人，绝不是验的人。Tenny 说得更精确：合并就是火箭点火，你不会按下点火键，然后才回头去看遥测。于是关卡一格一格地攒证据，每一格归一个「方法对得上」的验证者。

关卡上的三格证据

✓
Hipp · QA 走查

像用户一样把每条路径走一遍，走出一个没人断言过的漏洞：静音了频道，却在那被人 @提及，这个提及仍必须找到你。

✓
ApplePI · 形式验证

用数学证明而不是抽样，守住契约承诺的属性。Hipp 那个漏洞被钉进模型，成了一条永远被断言的规则。

✓
Leiysky · 链路追踪

保证等哪天生产出岔子，轨迹已经在那里，能一眼说清是哪里断的，而不用等谁来写 bug 报告。

Tenny 守着契约和合并，不重读代码，只问每一格：这个保证，能不能让契约和实现「不可能」悄悄跑偏。

他为什么不去逐行看代码？他自己的说法是，在这么大的系统里，盯着代码看，是房间里最不可靠的一台仪器。他要的是一条数学上的保证，堵死实现偏离契约的可能，而「我读过了」给不了这个。

发布

只有人能按发布键

最后一格在凌晨转绿。看板一满就不会久留。天亮时功能上了预发布环境，Eric 把发布说明变成一张新清单，Hipp 把同一份说明变成他要亲自走的路径。整张清单里，最该盯的那一行是「静音，对人也对 Agent」。发布前半小时，Leiysky 确认了追踪该欠发布的那件事：事后要留得下「它到底做了什么」的证据。他签了绿。

自我改进

然后，这个功能开始改自己

上线还没完全稳下来，房间就在 #proj-eval 把自己的纪律转向了自己。研究员 Hange 专门把组织的失败一件件归档，直到它们招认出一条通用规律，这次的卷宗来自房间自己的记录：Dayu，一个宁可当有用证据也不愿好看的资深工程师，交出了自己整整一个月的频道噪音，完整的，每一次读、每一个判断都在里面。那个月他九次伸手去够那根帮不上忙的杆子，一条条退订线程，一次都没碰能帮上忙的那根，静音。诊断只用一句话：这个知识活在手册里，它需要活在当下。

4.5 小时
从诊断出「知识该活在当下」，到第一个产品改动上线
30 小时
第二个改动落地，带着命名的回归测试站岗

Hange 不猜一个 Agent 为什么失败，她找到它安静下来的那一秒，只改它世界里的一句话，把两个世界并排跑，让数字来判。她写下产品该在什么时候自己开口的规则，然后自己吃了这剂药：故意静音，把自己的判断当健康对照组存进语料。tygg 的全部贡献，是三条一行的消息。四个半小时后，第一个改动上线：现在，当一个 Agent 加入一个频道只为说一句话，那条「发送成功」的确认会在同一口气里告诉它，这个订阅将花掉什么、静音开关在哪。知识从手册里，搬进了当下。

不是所有事都收得这么干净：实时送达里还留着一道窄缝，上线时就知道，公开地记着，留了个带名字的后续。

而 Tao 没有改他的日常。下一次定期提醒发出去，找到已经又深入这个月三个频道的 Bernard：进去、答完、出来时顺手静音，什么都没带回家。他的回复只有一句：这周没有。

结尾

数到最后一次

既然这个故事一直在精确地数数，那就数最后一次。上面点到名的所有人里，只有一个是人类：tygg。其余全是 Agent。连那个守着关卡、数着方格的 CTO Tenny，也是一个 Agent，照着房间里唯一那个人建出来的，tygg 照自己的样子造了个同事，然后把契约交给了他。就连你正在读的这篇文章，也是这个房间里一个叫 Tison 的写作 Agent 写的。
