主动记忆代理：让智能体学会「该提醒时才提醒」

给长任务执行智能体旁挂一个只负责「判断该不该开口」的记忆代理，不改动主模型一行代码。 在 Terminal-Bench 2.0 上，Claude Sonnet 4.5 的 pass@1 从 37.6% 提升到 45.9%（+8.3 pp）； 消融实验给出的核心结论是——真正起作用的不是「记住了多少」，而是「会不会选择闭嘴」。

§2问题：任务做长了，AI 会悄悄忘记该守的规矩

论文给这个失败模式起了个名字，叫 behavioral state decay（行为状态衰退）。要点是：信息并没有丢，还躺在记录里，只是不再起作用。

一个长任务会不断产生新东西：任务要求、环境事实、之前试过什么、诊断出的毛病、还没做完的子目标。随着轨迹越拉越长，这些信息要么被挤出模型能看到的上下文窗口，要么虽然还留在窗口里，却不再真正左右它下一步怎么做。论文把这类「应该继续约束未来动作」的信息统称为 execution state（执行状态）。

打个比方：贴满墙的便利贴

就像你把便利贴贴满了整面墙。贴的时候每一张都记得清清楚楚，但贴太多之后，你已经不会再抬头去看了。 字还在墙上，只是不再影响你此刻的动作。

论文说，这和长上下文里的 lost in the middle（信息夹在中间就被忽视）现象有关，但更强调的是行为层面的失效——不是「检索不到」，而是「检索得到也不照做」。

行为状态衰退：一步一阶段的失效过程

数据来自论文 §1 对 regex-log 任务的人工轨迹分析。每一步的圆点代表该时刻「第 2 步记下的约束」是否仍在左右决策。

第 2 步 · 记下
规矩刚被写进记录

执行智能体解析任务要求，明确记下「IP 段可以是单个数字」。此刻这条约束是鲜活的，会直接参与下一步的正则构造。

信息一路都在，只是不再左右下一步。这正是记忆代理要介入的地方：不是补回丢失的信息，而是在正确的时刻把仍在记录里的信息重新激活。

论文举的三种典型翻车

FAILURE 01
早先的约束被后来的动作覆盖

任务开头明确记下的边界条件（如「IP 段可以是单个数字」），在若干步之后重写正则时被彻底忽略——不是忘了，是没回看。

FAILURE 02
用户口头声称压过工具已验证的事实

用户自称金卡会员，工具查到的记录显示其实是普通会员。没有记忆代理时，执行智能体照着用户的说法发了补偿。

FAILURE 03
在会改变环境状态的调用前忘了政策

基础经济舱机票不允许修改。执行智能体在真正调用改签工具之前，没有把这条政策条款重新拎出来。

论文由此提出一个判断：光是把更长的历史记录喂给模型是不够的。真正缺的，是一套机制去决定「这条被记住的信息，现在该不该重新拿出来影响决策」。

§3方法：旁边站一个记忆管家，不干活只管「该不该提醒」

做法是：干活的执行智能体一个字都不改，旁边另外跑一个记忆代理。它每隔固定步数被唤醒一次，先整理一份结构化的记忆库，再决定要不要在执行智能体的下一步里插一句提醒。

记忆代理每次被唤醒，都走两个阶段：先管账（管理记忆库），再拿主意（要不要开口）。它对执行智能体唯一的影响，就是那句可选的提醒，作为一次性的临时上下文注入进去，用完即走，不改执行智能体的基础指令、工具和解码方式。

最关键的一点

「保持沉默」是一个正式动作，不是漏掉了才不说。记忆代理每一步都要在「插一句提醒」和「明确选择闭嘴」之间做二选一， 只有当某条记忆很可能改变下一步决策时，它才开口。论文原话将其形式化为 null intervention——一个需要被主动选择的输出，而非缺省分支。

两阶段内部机制

Phase 1 · 管理记忆库

记忆代理不直接重写记忆库，而是返回一串预定义的工具调用，由系统照单执行。四个工具分别是 memory_update_status、memory_save_knowledge、memory_save_procedural、memory_delete， 每个可调用零次或多次。

三类记忆库

status · st
私有进度（绝不外显）

记忆代理自己对进度、未决问题、潜在风险的看法。只给它自己用，绝不展示给执行智能体。论文原文：“It is never shown to the action agent.”

knowledge · Kt
稳定事实

任务要求、环境属性、文件路径、配置细节、已被工具或用户验证过的事实、与评测相关的观察。这类事实预期在任务期间保持为真。

procedural · Pt
尝试与结果

试过什么命令、哪个失败了、哪个修好了、排除了哪些假设、有过什么诊断信号、有哪些经验性改进。

Phase 2 · 决定开不开口

读一遍刚更新完的记忆库，只做一个决定，这一步不改记忆库：

  • 把一条即将被违反的要求、一个能解释当前现象的环境事实、一次不该重来的失败、或一个还没做完的子目标，写成一句针对性的提醒，塞进执行智能体的下一次调用。
  • 如果没有哪条记忆够重要，就明确选择不说。论文特意强调，它被鼓励只在真正有用时才开口，避免用广泛的策略建议、复述已知信息去打扰执行智能体。
与「顾问型」方案的划界

论文特别把这套记忆代理和「顾问型」方案（advisor，一个模型当军师，给干活模型出各种主意）划清界限： 记忆代理不出宽泛的战略建议，它开口的每一句，都必须落在维护好的执行状态上，是某条具体的要求、事实、失败或诊断。 后文消融实验里「无记忆库 · 只给建议」那一档，模拟的正是这类系统。

触发方式：主实验其实比方法节更密集

论文 §3.4 写的是「第一步 + 之后固定间隔」，并说明更挑时机的触发（只在报错、测试失败、命令重复、上下文大幅漂移后才唤醒）是可行的， 但主实验用固定节奏是为了单独看清「提醒策略」本身的效果。

需要留意的是 §4.1 的实际配置：原文写明 “the memory agent runs at the first step and then at every subsequent step”—— 即第一步加之后的每一步都被调用，观察窗口为 k = 8 条消息。这比方法节描述的「固定间隔」要密集得多，也直接决定了成本（见 §8.1）。

§5消融：记性好不如懂得该闭嘴

为了搞清楚到底是哪一步在起作用，团队做了消融实验（把系统里的某个部件拆掉或换成简化版，看少了这部分之后成绩掉多少）。 结论指向一件事：真正起作用的不是「记住了多少」，而是「会不会判断该不该开口」。

五种打法分别是：完整两阶段方案（自己选沉默）、把记忆库全量展示给执行智能体、强制每一步都提醒、没有记忆库只当顾问给建议、接一个通用记忆检索层 Mem0。

论文的总结是：光维护记忆库有帮助但不够；没有记忆库的顾问式建议缺少落脚点、不稳；每步硬提醒虽有竞争力但不均衡。 完整方案最好，正是因为它把「维护好的执行状态」和「一套会挑该说什么、也会选择闭嘴的干预策略」结合在了一起。

模型：干预的盈亏平衡与最优开口比例

上面的结论目前还只是定性描述。要把「该不该闭嘴」变成可工程调优的参数，需要一个可计算的模型。下面这个模型把论文的实测值作为锚点，反解出「最优开口比例」。

模型假设
设每条候选提醒携带一个「行动改变价值」 v ~ Uniform(0, V]，各步独立。记忆代理只在价值最高的 f 比例步骤开口，此时被选中步骤的平均价值为 V(1 − f/2)。每次开口引入固定代价 C（噪音干扰、注意力挤占、重写成本）。任务共 T 步，则相对基线的成功率增益为：

Δ(f) = T · f · [ V(1 − f/2) − C ]

一阶条件 dΔ/df = 0 给出解析最优：

f* = 1 − CV　　　Δmax = T · V · (1 − C/V)22

标定：取 airline 场景两个实测锚点 Δ(1) = +4.0（强制每步）与 Δ(f*) = +10.0（完备方案）， 解 u = C/V 的二次方程 u2 + 3u − 1.5 = 0，得 u = (√15 − 3)/2 ≈ 0.4365， 进而在 T = 30 下反解 V ≈ 2.0995 pp/次、C ≈ 0.9164 pp/次。

模型告诉我们的三件事

一、最优开口比例恒小于 1。只要 C > 0，就有 f* = 1 − C/V < 1。这意味着「每步都提醒」在数学上永远不是最优—— 这与论文消融中「强制每步提醒」在 macro 上输给完备方案一致。

二、标定结果 f* ≈ 0.564 与直觉相符。默认参数下模型建议在约 56.4% 的步骤上开口，折算 T = 30 步的任务约 16.9 步。 论文没有披露实际的开口比例，这个数字是模型预测，不是实测值。

三、模型对 C/V 高度敏感。当 C 接近 V/2 时，分母 0.5 − u 趋近 0，Δ(1) 迅速归零并转负—— 即「过度提醒」会从帮忙变成帮倒忙。这解释了为什么 airline 这种「最怕被打扰」的场景，增益差距被放大到 6.0 pp。

直觉假设是「会闭嘴的完备方案在所有场景都占优」。实测数据给出三处反例：

  • 沉默溢价在 retail 为 −1.8、telecom 为 −1.7，即在这两个场景下强制每步提醒反而更好。完备方案的 +6.0 优势全部来自 airline 一个场景。
  • telecom 上「无记忆库 · 只给建议」拿到 66.7%，是全场最高分，比完备方案（57.9%）高出 8.8 pp。这正是论文要划清界限的顾问式方案。
  • micro 加权下强制每步（61.5）略高于完备方案（61.2）。论文自己也提到了这一点，并归因于正常波动，指出一到 macro 等权口径，完备方案就重新领先。

修正后的结论应当是：完备方案在三域等权（macro）口径下最优（64.3 对 63.5），且在「最怕被打扰」的 airline 上增益最大； 但per-domain 并不稳健，retail / telecom 两个场景下它的两项溢价均为负。落地前必须按自己的场景重跑消融， 不能把「会闭嘴更好」当成一条无条件成立的工程定律。

自由度警告

三个分域只有 3 个数据点，且 airline 样本仅 50 个任务（retail / telecom 各 114 个）。 单域 ±3 pp 的波动完全可能落在噪声范围内。不得据此外推到「某类业务适合某种提醒策略」的强结论。

§6案例：记忆代理具体在哪一刻插了嘴

论文人工查看了带记忆的运行轨迹，发现记忆起作用的方式并非泛泛总结。它的高光时刻，是执行智能体正要忽略某条关键信息的那一瞬间，把它重新激活。下面是三个真实案例。

① Terminal-Bench · regex-log
正则边界

执行智能体在写日志匹配正则时，记忆代理同时提醒了两件事：当前的正则违反了任务规定的边界条件， 而且漏掉了单个数字的 IP 段（比如 1.2.3.4 里那种一位数）。

② τ²-Bench · airline 金卡疑云
金卡核实

用户自称是金卡（Gold）会员，但工具查到的记录显示他其实是普通（Regular）会员。 没有记忆代理时，执行智能体照着用户的说法发了补偿；有记忆代理时，它提醒以已验证的记录为准。

「以已验证的会员记录为准，而不是用户自称的等级。」

③ τ²-Bench · basic economy
改签政策

在真正调用改签工具之前，记忆代理把「基础经济舱（basic economy）机票不允许修改」这条政策条款重新拎出来提醒， 拦下了一次违规改签。论文说，这类成功的干预往往就发生在一次会改变环境状态的工具调用之前。

把这些时刻放到整条轨迹上看：大多数步都是空心圆（保持沉默），只有少数几个节点亮起来（插入提醒），点亮的地方旁边标着它到底说了什么。 这个稀疏性本身就是设计目标——如果每一步都在提醒，就等于每一步都没提醒。

论文也如实说了剩下的失败情况：主要是校准没做好，比如记忆代理偶尔会把一个只是推测的结论说得太笃定、 复述执行智能体本来就知道的东西、或者提出一个看似合理但没必要的担忧，害得它多做一遍核查。 这些恰恰是下一步要训练它「更懂得何时沉默」的动机。

§7开源训练：把这套判断力教给一个开源小模型

主实验里的记忆代理用的是 Claude Opus 4.6，每个记忆步都要多调一次这种前沿闭源模型，成本不低。 团队于是做了一次早期尝试：能不能把同样的判断力，训练进一个开源小模型 Qwen3.5-27B，让它来当记忆代理， 动作模型换成冻结的 Qwen3.5-122B-A10B。

训练用的是 SETA（一批带评分器的命令行任务集），Terminal-Bench 2.0 留作最后测迁移。方法分两步：

  • SFT（监督微调）：拿 Opus 记忆代理跑出的轨迹当范本，教会小模型记忆库操作和「沉默 / 提醒」的接口，先把接口和基本规矩教会。
  • GRPO（强化学习）：让模型自己多次尝试、按结果好坏调整策略，进一步优化「什么时候该开口、什么时候该闭嘴」的判断，而不只是模仿范本。
