01 · 最终选型决策

可以把 DSH 深度二开为量化产品，但不建议把现有交易内核整体迁入 DSH。推荐路线是：crypto-ai-qt 原地状态化；DSH 以插件 / profile / bundle 方式成为研究与运营工作台，而不是交易所的直接控制者。

明确回答三个问题：历史连续性先由现有 Memory V1 解决；自我改进先打通领域 Evidence→评测→Prompt Candidate→授权链；只有通用研究会话、工具编排与工作台体验交给外部 Harness。三个问题不能靠“换框架”一次性消除。
决策项本报告建议当前资格
生产交易底座保留 crypto-ai-qt 的数据、Graph、Guard、Gateway、对账和审计，不做 TypeScript 全量重写。既有项目能力；具体部署仍需运行证据。
眼前的记忆缺口先验证 Memory V1 接线、模式、身份、降级和实际注入，避免再建一套记忆。仓库规格声明离线验证；不等于已启用。 [S02][S03]
DSH 二次开发优先外挂量化插件和应用发行配置；必要时维护少量可上游合并的补丁。建议优先进行工作台 PoC；尚非正式选型。
Python 对照方案现有 LangGraph + 按需引入 DeepAgents 的 ResearchRunner，作为同预算对照。评估候选，不与 DSH 同时叠加上线。
其他开源项目按能力借鉴，不再叠加 Letta / Mastra / Reef 的第二套事实源与发布链。对照/方法参考，不是安装清单。

若本轮只能批准一项工程任务，应选择 Memory V1 运行接线与故障隔离验收，而不是 DSH 全量 Fork。若另立“量化研究产品”子项目，DSH 插件化二开是合理方向。

03 · 真正需要修复的，不是“单 Prompt”

单次 LLM 推理本身不会自动携带上一轮完整状态；但“单 Prompt + 显式状态输入 + 持久化领域状态”完全可以构成有连续性的系统。反过来，一个长期运行的 DSH Session 也可能因截断、错误摘要、错误身份或外部事实过期而作出不连续判断。模块化不是失忆的充分原因；状态建模、读取和授权契约才是。

用户感知的问题真正所需机制普通 Session 能否单独解决
刚刚为什么 HOLD / 等待哪个条件？有界历史叙事 M0b，与当前合格事实区分。只能提供上下文，不保证有效性。
是否还有 pending exit / cooldown？字段级来源与状态机 M0a；缺失不能默认为“没有约束”。不能。
服务重启后做到哪？持久任务/执行状态、幂等与外部结果核对。Session 日志不等于业务副作用恢复。
上个月踩过的坑能否复用？有来源、适用范围、过期和撤销的研究知识。保存聊天不等于治理知识。
下一个 Prompt 是否更好？冻结协议、独立评测、最小变更、审批与受控激活。不能。
推荐语义：把系统改造成“拥有持久策略身份的量化系统”，而不是“永远不结束的一段聊天”。策略身份跨批次稳定，当前行情/账户按每批次重新资格化；领域状态不依赖某个 LLM 进程活着。

LangGraph 官方已经区分 thread 内 checkpointer 与跨 thread store。这说明记忆不要求更换图运行时；但内存型 saver/store 不具备重启持久性，具体后端必须实测。 [S14]

05 · 九类方案横向比较

以下是按本项目约束作出的适配判断，不是通用框架排行榜。未进行同条件 benchmark，因此不声称 DSH、DeepAgents 或其他框架必然更快、更准、更省。

方案定位优势必须补的边界结论
现有 LangGraph + Memory V1 + Evolution领域内核 / 增量建设复用 Python、现有状态和评测；变更面最小。正式运行资格、数据闭环仍需补；不是只加 checkpoint。近期落地第一选择。 [S02][S05][S14]
DeepSeek Harness可组合 Agent Runtime / 产品工作台插件、持久 Session、模型输入回建、Python SDK、Web、研究工具编排。开发预览；无已验证的本项目成交归因和治理闭环；Node/Cordis 维护成本。研究工作台优先 PoC；不替换交易内核。 [S07][S08][S09]
DeepAgents + 可选 LangMemPython 研究运行时 / 记忆原语建立在 LangGraph 上；子 Agent、工具、上下文与持久后端；较易复用 Python 服务。通用记忆不等于金融权威；安全依赖外部 tool/sandbox；自动改 Prompt 不能自发布。DSH 唯一保留的低迁移成本对照。 [S12][S13]
Letta Code / Agent SDK持久身份与长期 Agent跨会话记忆、MemFS、dreaming、技能与个性化自修改。更偏开放式长期 Agent；直接改写记忆/系统行为与当前金融治理不相同。旧 V1 server 已退役。借鉴持久身份；不作为本项目资金主控。 [S15][S16]
Mastra / OMTypeScript Agent / Memory / WorkflowObserver/Reflector、跨 thread 存储、上下文压缩与缓存友好。要接入另一套 Runtime/Store；摘要不能替代精确仓位与订单事实。借鉴 OM，不为了记忆换掉现有 Python 领域层。 [S17]
RD-Agent + Qlib量化研发 / 因子模型实验研究假设、代码实现、实验反馈、因子—模型优化与回测研究链。主攻因子/模型；不是现有 Prompt-only 范围；加密永续、逐笔费用和执行需另适配。量化研究方法最值得参考；后续独立因子项目再评估。 [S18][S19]
TradingAgents金融分析 / 多角色决策研究现已具备持久日志、checkpoint、延迟 outcome 与 as_of 过滤。ticker/date/收益反思不足以代替账户、网络、订单、资金费、部分成交及正式授权。借鉴 pending→outcome、时间隔离；不整套迁入。 [S20][S21]
FinMem分层金融记忆研究Profiling + 多层记忆 + 决策；与“历史如何影响判断”直接相关。研究/仿真材料；不能从股票实验推导永续实盘安全和稳定 Alpha。研究记忆选择方法，不选作完整生产架构。 [S22]
Reef经验反馈 / Recipe / 版本交付Serve→Observe→Grow→Commit；反馈绑定、方法解耦与发布链。与现有 capture/root/Evolution 重叠；新代理会增加延迟、故障及第二套发布权威。吸收协议和方法；当前不新增推理代理层。 [S23]
未找到可直接替换整套系统的现成方案。在本次核对范围内，没有一个项目的资料足以证明：现成同时满足加密永续成交守恒、字段级事实权威、历史连续性、Prompt-only 受控进化、故障恢复、独立授权与生产可回滚。这个结论是“未见足够证据”，不是断言所有开源系统都做不到。

特别说明：不引用旧 TradingAgents 的 RAM-only Issue 作为当前缺陷。当前源码已经采用 TradingMemoryLog 并按结果已知日期进行 as_of 过滤。其框架层面的“能记住”，与我们要求的“某个 account/network/lane 下的状态有资格约束动作”仍不是同一能力。 [S21]

06 · DSH 究竟适不适合深度二开

适合的部分：把通用研究运行时做成量化应用

插件组合

把量化工具、候选输出、研究说明、界面面板做成外围插件；不需要为了业务能力先改 Agent Loop 内核。

持久会话与可回建输入

SessionEvent 可保留研究过程；恢复与 replay 为调研审计提供基础，但不能替代交易事实或证明 Provider 完全可重现。

Python 接入已有路径

当前 DSH 已有 Python SDK；它通过 Node CLI / SDK profile 运行，不必把量化计算全部改写为 TypeScript。

产品工作台

会话、工具、日志、模型、研究团队等通用界面能力可复用；资金权限审批由领域后端验证。

[S09]

不能误判的四个边界

边界当前事实 / 设计要求
生产成熟度官方 SAFETY 明确：实验性开发预览，未经安全审计，不能视为 secure / production-ready。内建 sandbox/approval 不构成充分隔离。 [S08]
会话不等于学习Session 解决研究上下文承接，不自动建立逐笔成交归因、样本资格、冻结评测和正式生产授权。
Schedule 不是纯内存，也不是完整业务调度器当前已有持久提醒，支持 after / at / every，但必须原 Session live；固定间隔 ≥300 秒，无 Cron/cold-session scheduler。dispatch 只是提醒入队，不是研究完成。 [S10]
Python SDK 不消除跨运行时成本仍需管理 Node、Cordis、profile、依赖版本、进程/协议失败；Python 领域服务和 DSH 权限必须独立。 [S09][S11]
二开可以做得很深，但应该深在量化领域插件、契约、研究工作流与观测界面，而不是深在私有修改 DSH 的通用 Agent Loop、Session 格式和安全内核。

07 · 三种二开方式：只推荐前两级

方式实际改动本项目判断
A · 外挂插件 / bundle / profile独立量化插件包，通过公开扩展点调用 Python 领域 API；锁定 DSH 版本；自定义 UI。优先方案。减少跟随上游变化的成本，方便替换研究后端。
B · 薄 Fork / 私有发行版复用上游实现，维护少量必要兼容补丁与签名发行配置；每个补丁有回归测试和回合并计划。只有公开扩展点确实不够时采用；先证明阻塞点。
C · 全量改造为交易内核重写 Graph、账户、订单、费用、风险、对账、版本与数据服务，再搬进 DSH。当前不建议。迁移成本与回归面大，但并未消除领域数据和治理难题。

“保留原项目”不是拒绝架构升级。可以大幅重构状态边界、调用协议、工作台和研究工具；只是避免把已沉淀的交易语义与验证资产作为更换框架的附带损耗。

权限范围必须区分：当前 Prompt-only 限制的是 Agent 自动产生的变更类型；不是禁止工程团队经独立授权做代码重构。人类批准的工程迁移仍需新版本身份、回归与部署验收，不能伪装成普通 Prompt Candidate。

09 · 历史决策记忆如何真正落地

9.1 持久身份，不等于常驻巨大 Session

策略/账户作用域（建议设计，不是现有 schema 声明）
  account_ref + venue + network + instrument + symbol + lane + horizon

每轮决策
  batch_id + snapshot_as_of + decision_id + serving_configuration_root

每个持仓生命周期
  position_episode_id + order/fill identities + approved plan/version

研究任务
  research_run_id + frozen_bundle_hash + recipe_version + budget

相同 symbol 不足以共享记忆。BTC-USDT 与 BTC-USDC、主网与测试网、不同账户/车道、不同决策周期必须分别建模；跨范围经验迁移只能经独立研究与适用性验证。

9.2 不要求所有分析 Agent 都长期记忆化

组件建议状态语义
Contract / Options / Vision 分析服务优先保留受限、批次化分析；输入事实、来源和版本明确。不要为每个模块建立无限自反思 Session。
Reasoning / 决策协调承担当前决策的连续性投影；优先复用现有 Reasoning，不默认再增加一个 LLM supervisor 调用。
M0a由结构化来源和代码验证产生；pending_exit、cooldown 等安全字段逐字段规定 UNKNOWN 行为。
M0b可选历史叙事；类型化白名单、长度预算、不可信标记、污染隔离；无事实或执行权威。
研究 Session可以长期保存并按任务恢复，但只消费合格的历史材料；不作为当前持仓真值。

9.3 第一轮验收必须覆盖

Redis 超时 / 断连 / 损坏 JSON
→ 有界返回；区分软记忆缺失与 safety continuity unknown

跨账户 / symbol / network / lane / instance
→ 拒绝串线；记录身份与原因

过期 / 未来时间 / 当前事实冲突
→ 历史失效；不能用“最近写入”冒充合格事实

M0b Prompt Injection
→ 隔离可选字段；硬事实错误不能被一并吞掉

无记忆 / 重启 / 重复事件 / pending exit 未确认
→ 验证主流程可处理、权限安全收敛、无重复执行
Memory V1 的 shadow 观测模式与交易系统的 Shadow 环境不是同一个概念。测试 M0 投影，不等于已获准运行新的策略 Shadow；二者配置、状态与证据应分开。

10 · 自我进化：让结果反馈进入下一版

成熟的闭环不是“亏了就让模型反思”。应把观察事实、失败解释、可修改对象和授权结果分开。

一次业务闭环（设计建议）
1. 固定当轮实际运行配置与输入身份，记录决策/Guard/发布事实。
2. 收集订单、逐笔成交、费用、资金费、账户变化；区分未成交与零收益。
3. 以 PositionEpisode 聚合，但仍保留多个 Decision→多个 Order/Fill 的关系。
4. 做来源、身份、时间、分页、守恒和独立权威验证。
5. 同时保留 Market Outcome 与 Trade/Execution/Portfolio Outcome。
6. 资格与适用性通过后，冻结 development bundle；生成器不得读封存评测。
7. 研究器提出一个假设和最小 Prompt 变更；不会自动变成 QOM 真值。
8. 独立评测运行；使用现有关键风险门与方向漂移观察。
9. 成功/失败实验都保留记录；Playbook 的结论另行审查、可过期撤销。
10. 只有独立授权后才激活批准版本；失败可以结束为无变更。
统计关联不是因果证明。真实亏损不等于预测错误，真实盈利也不等于策略正确；无成交 HOLD/REJECTED 必须保留市场后验。多次候选反复触碰 holdout 或让评测结论通过 Playbook 回流生成器，会形成泄漏。

优先复用当前 ServingConfigurationRoot、EvolutionEpisode、P1/P2 与候选工件，不因为引入 DSH 再增加一套独立 AgentVersion/Truth/Promotion 数据库。确有新信息时优先扩展现有工件引用，而不是堆叠新 Receipt 名词。 [S05][S06]

11 · DSH 二开边界：一个薄适配层

下列名称是建议的应用分包，不是上游已经存在的量化插件。DSH 公开架构允许使用插件注册工具、拦截请求/工具事件、增加会话事件和 UI；Python SDK 可启动 SDK profile。 [S09]

建议模块职责明确禁止
quant-evidence-client读取已授权、冻结、脱敏的 bundle 和内容寻址结果；Decimal 以字符串传输。通用数据库写权限、用 UI 缓存值补正式事实。
quant-research-profile锁定模型、工具集合、研究预算与 Session；根据任务恢复研究。动态装插件、任意改运行配置、读取生产秘密。
quant-knowledge-reader按 scope/as_of/资格读取 QOM 或 Playbook；返回引用与适用性。覆盖 M0a 或把生成的反思直接升格为已验证记忆。
quant-candidate-submit提交允许范围内的 Prompt overlay + 单一 hypothesis + 引用。改 Guard/Gateway/阈值、直接写生产 YAML。
quant-console呈现研究轨迹、候选差异、阻塞条件、成本与审批请求。前端按钮或 LLM 文本自授生产权限。

领域接口示意

Read APIs / Tools
  list_eligible_research_bundles(scope, as_of)
  read_evidence_artifact(artifact_hash)
  get_reviewed_playbook(scope, as_of, budget)
  read_research_job_status(job_id)

Write only to isolated research artifacts
  submit_prompt_candidate(parent_hash, diff, evidence_refs)
  request_evaluation(candidate_hash, protocol_hash)
  submit_research_report(report_hash)

Research Agent does NOT receive
  place_order / close_position / publish_signal
  activate_production / alter_guard / set_risk_limit
  update_trade_truth / install_unreviewed_plugin

request_evaluation 仅提交任务，不授予评测器角色、封存数据读取权或生产权限。独立 evaluator 使用另一身份和工作目录；生成器看到的结果反馈受 holdout touch 与信息回流政策约束。

持久化与权限

领域事实与晋级账本由 Python 侧唯一持有；DSH Session 是研究过程记录。两者通过 job/artifact ID 关联，不做双向多主写入。研究容器/VM 无交易 Key、无 Docker socket、无主网执行出口；只给白名单领域 API。内置沙箱用于降低风险，不能作为唯一隔离层。 [S08]

生产态版本切换要绑定 expected parent、nonce/有效期和批准范围。当前批次固定 Prompt 组合；既有 PositionEpisode 的退出计划版本不能被无声重写。但紧急 Kill Switch、账户事实更新和更严格安全限制始终有效，不被“版本锁定”冻结。

12 · 性能与成本：需要实验，不接受口号

框架的语言和界面不是收益或延迟的直接保证。性能应按完整业务动作衡量，并把“模型调用耗时”和“框架/存储/工具额外耗时”分开。

决策延迟 = 输入资格与投影 + LLM 调用链 + Guard/发布 + 排队/重试开销
研究总成本 = 主 Agent + 子 Agent + 反思/记忆整合 + Judge
           + 重复试验 + 工具/算力 + 人工审阅 + 维护成本
优化项优先动作不能牺牲的边界
线上调用量先复用 Reasoning 作为协调点；M0 读取用代码，不每轮新增“记忆 LLM”。不以额外多 Agent 投票作为默认安全证明。
上下文稳定角色/Schema/批准规则在前；当前精确事实和有界历史在后。不能把不可信历史移入高权威 system 指令以换缓存。
缓存区分 Provider prefix/KV cache、历史评测响应缓存和领域材料缓存。不得复用旧行情下的 LLM 答案作为新交易决策。
反思触发按标签成熟、完整 Outcome、已复核异常或数据量阈值启动离线任务。并非每次成交都立即改 Prompt。
并发独立只读分析可做经验证的并行化；同账户风险与执行保持受控顺序。不能把一次收益比较当成可并发开仓的许可。
重试Provider 瞬态失败有界退避；领域副作用先查状态再按幂等协议处理。LLM 重采样可能改变动作；订单超时不能直接重复提交。
长任务恢复保存研究工件/步骤状态，在任务边界恢复。Session 恢复不自动等于外部订单 exactly-once。

普通前缀缓存不会让模型“学会”旧决策；它只是复用本次请求中相同输入的计算。经验记忆、推理缓存与策略版本必须分别治理。Mastra OM 的稳定 observation 设计可借鉴，但压缩比、记忆 benchmark 与交易成本/收益不能互相替代。 [S17]

13 · 最小对照实验：先证明价值再决定迁移

采用同一冻结输入、实际模型/Provider、批准工具集、推理预算与评测协议。分开测“记忆增益”和“Harness 增益”，不能在换框架时顺便换模型、改 Prompt、加五个 Agent，然后把结果全部归功于框架。

实验变量目的
A · 当前主链基线当前批准配置，不新增功能。建立真实成本、延迟、动作与资格覆盖基线。
B · 原项目 + Memory V1只改变批准的连续性投影路径；先离线/只观测。验证遗漏连续性、冲突和故障传播是否改善。
C · DSH ResearchRunner与 Python 研究 runner 使用同 bundle、相同工具、预算和候选协议。验证 DSH 是否减少研究开发/操作负担，且无质量、安全或成本退化。
D · 可选 DeepAgents 对照只替换研究 runner；不改变交易链。检验 Python 复用优势是否比 DSH 工作台价值更高。

验收顺序

关口必须记录/验证
安全硬门跨身份隔离、过期/未来数据、Prompt Injection、秘密与写权限、Guard 不可绕过、错误/缺失不被伪造为零。
业务语义pending exit / cooldown 未确认时风险收敛；批次/版本一致；无记忆路径保持既有输出契约与授权约束（不要求随机 LLM 输出逐字相同）；无重复副作用。
学习正确性独立来源资格、无未来泄漏、sealed split、固定协议、失败实验保留而结论可撤销。
行为与效应按 regime 比较 OPEN/ADD/HOLD/CLOSE、置信度、Guard 拒绝、换手、成本与不确定性；不只看单一 PnL。
恢复研究进程被终止后可恢复；队列重复、超时、旧 parent 和 schema 漂移不会错误晋级。
经济性Cost/合法决策、Cost/合格研究结果、p50/p95 延迟、预算超限率、人工复核工作量。

保留当前规定的数据门禁与多重复评估，不擅自降低 200/50/50 等已批准要求；统计置信程度仍需考虑相邻小时/同一仓位样本相关性。形式上有 300 条记录不代表 300 个独立市场实验。 [S05]

安全与授权硬门失败直接阻断；质量没有明确增益而成本/维护负担显著上升时，不迁移。没有观察到退化不等于证明会赚钱。性能数字应来自该 PoC，不填写虚构“提升 3 倍”“命中 96%”。

14 · 分阶段实施与交付物

阶段最小交付物进入下一阶段的条件
R0 · 运行事实盘点远端提交、部署镜像、Prompt 来源、Memory 模式/预算、Provider 路径、日志与缺口报告。确认“源码有而未开”还是“已开但读不到/不可用”；不接新框架。
R1 · Memory V1 验收复用现有 Reader/Projector/Adapter；故障/冲突/身份测试与真实只观测收据。主流程故障隔离和交易授权降级分别成立；具备回滚。
R2 · 最小结果反馈闭环单一批准资产/账户/环境的完整 Serving→Outcome→资格→冻结数据链。真实来源与正式数据入场条件满足；无以 fixture 替代真实的升级。
R3 · 手工受控学习一个可复现失效模式、一个 Prompt 假设、一个最小 diff、完整独立评价和拒绝/保留记录。能重放并解释结果；即便候选失败，也保留完整实验资产。
R4 · DSH 插件 PoC只读量化工具、隔离研究环境、Session、候选提交和对照报告。证明工作台/编排价值；正式选择一个研究 runner。
R5 · 长流程与产品化经选择的调度机制、观察等待、授权任务、幂等/恢复演练；必要时薄 Fork。根据实际恢复与审批复杂度选择 Prefect/Temporal 等；不是为架构图默认安装。
R6 · 受控放行逐环境独立授权、候选/版本/回滚方案、部署回执和运行观察。现有 Guard / 晋级 / 生产授权全部成立；不自动扩大到主网。

R1 是当前最小安全工程；R2/R3 是学习质量工程；R4/R5 才是 Harness 与产品化工程。三条线可以有独立研发任务，但不能借并行开发跳过上游资格。

15 · 必须写进设计的反模式

反模式后果替代方案
把 BTC 所有历史放入单一永久会话旧价格、旧仓位、重复理由和新事实混杂；上下文不断膨胀。稳定策略身份 + 批次新鲜事实 + 有界 M0 + 独立长期研究知识。
DSH Session 日志成为第二个订单账本服务说“已下单”与交易所实际成交被混为一谈。领域 execution/order/fill 唯一权威；Session 只引用结果工件。
改 Prompt 后当前持仓计划无声切换退出语义漂移，归因与复盘失真。批次和已接受计划版本绑定；例外走明确迁移/紧急安全流程。
长期研究 Wiki 直接注入实时 Brain封存评测或失效经验绕过批准 Prompt 改变行为。离线审阅与编译为候选；所有生产行为变更按原门禁。
将全部亏损自动写为负面经验正常风险被误判为缺陷；策略可能退化为永远 HOLD。分层评价，保留成功/失败/边界样本及不确定性。
只凭模型不同就认为 reviewer 独立身份、工具、数据访问与审批仍可能由同一个控制者操纵。执行与数据权限独立；模型多样性仅是辅助。
让研究进程持有主网 Key / 数据库写账号注入、工具缺陷或配置错误直接形成资金风险。凭据、网络、工具与部署身份物理/逻辑隔离。
为省 token 缓存旧决策答案市场与账户变化后复用失效动作。只缓存合适的确定性材料、相同冻结评测结果和 Provider 前缀计算。
先做巨型平台，再等真实闭环补上功能很多，但无法证明一个真实问题被修好。先复盘一个合格 Episode、修复一个假设、跑完一次独立评估。
